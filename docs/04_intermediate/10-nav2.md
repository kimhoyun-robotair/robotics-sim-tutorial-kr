# Gazebo와 Nav2 연동

> **난이도:** 중급  
> **Gazebo:** Harmonic  
> **ROS 2:** Jazzy  
> **선행 학습:** 다중 로봇

## 학습 목표

- Nav2가 요구하는 map, odometry, TF, LaserScan, velocity command 흐름을 연결한다.
- map YAML, AMCL, costmap, planner, controller parameter를 실제 코드에서 읽는다.
- `NavigateToPose` action의 성공과 abort를 구분한다.
- action 결과와 최종 pose 오차를 함께 검사한다.

## Gazebo와 Nav2의 책임

Gazebo가 Nav2를 대신하지 않는다. Harmonic은 물리, wheel odometry, LiDAR, simulation clock을 제공한다. Nav2는 map을 읽고 localization, global planning, local control, recovery를 수행한다.

```text
training.sdf ── Gazebo physics·sensor ── /scan, /odom, /clock
                                              │
training.yaml ── map_server ── /map           │
                         └── AMCL ── map→odom │
                                              ▼
goal ── planner ── /plan ── controller ── stamped cmd_vel
                                              │
                                              ▼
                                  diff_drive_controller
```

필수 TF는 `map → odom → base_link → lidar_link`이다. AMCL이 `map → odom`, DiffDrive controller가 `odom → base_link`, `robot_state_publisher`가 `base_link → lidar_link`를 각각 소유한다.

## 1. map YAML 읽기

실제 map 설정은 `examples/ros2_ws/src/tutorial_bot_gazebo/maps/training.yaml`이다.

```yaml
image: training.pgm
mode: trinary
resolution: 0.05
origin: [-5.0, -5.0, 0.0]
negate: 0
occupied_thresh: 0.65
free_thresh: 0.196
```

`resolution=0.05`는 한 pixel이 5 cm라는 뜻이다. `origin`은 image의 기준점을 map frame에 배치한다. PGM image와 실제 `training.sdf` fixture가 맞지 않으면 scan endpoint가 map wall과 겹치지 않고 AMCL pose가 흔들린다.

## 2. AMCL frame과 sensor topic

실제 설정은 `examples/ros2_ws/src/tutorial_bot_bringup/config/nav2_params.yaml`에 있다.

```yaml
amcl:
  ros__parameters:
    use_sim_time: true
    global_frame_id: map
    odom_frame_id: odom
    base_frame_id: base_link
    scan_topic: /scan
    robot_model_type: "nav2_amcl::DifferentialMotionModel"
    min_particles: 500
    max_particles: 2000
    set_initial_pose: true
    initial_pose:
      x: 0.0
      y: 0.0
      z: 0.0
      yaw: 0.0
```

`DifferentialMotionModel`은 2륜 `tutorial_bot`의 운동학에 맞는다. 4륜 Ackermann rover를 Nav2에 연결할 때는 controller와 motion model, footprint, 최소 회전반경을 함께 다시 검토해야 한다.

## 3. local·global costmap

local costmap은 odom frame에서 움직이는 rolling window이고, global costmap은 map frame의 정적 map과 obstacle을 사용한다.

```yaml
local_costmap:
  local_costmap:
    ros__parameters:
      global_frame: odom
      robot_base_frame: base_link
      rolling_window: true
      width: 3
      height: 3
      resolution: 0.05
      footprint: "[[0.24, 0.18], [0.24, -0.18], [-0.24, -0.18], [-0.24, 0.18]]"
      plugins: ["voxel_layer", "inflation_layer"]
      voxel_layer:
        plugin: "nav2_costmap_2d::VoxelLayer"
        observation_sources: scan
        scan:
          topic: /scan
          data_type: "LaserScan"
          marking: true
          clearing: true
```

```yaml
global_costmap:
  global_costmap:
    ros__parameters:
      global_frame: map
      robot_base_frame: base_link
      plugins: ["static_layer", "obstacle_layer", "inflation_layer"]
      static_layer:
        plugin: "nav2_costmap_2d::StaticLayer"
        map_subscribe_transient_local: true
      obstacle_layer:
        plugin: "nav2_costmap_2d::ObstacleLayer"
        observation_sources: scan
        scan:
          topic: /scan
          data_type: "LaserScan"
          marking: true
          clearing: true
```

footprint는 visual 크기가 아니라 collision의 바닥 투영과 안전 여유를 기준으로 정한다. 실제 몸체가 footprint보다 크면 planner가 통과 가능하다고 판단한 좁은 공간에서 충돌할 수 있다.

## 4. planner와 path follower

global planner와 local controller plugin을 이름으로 선택한다.

```yaml
planner_server:
  ros__parameters:
    planner_plugins: ["GridBased"]
    GridBased:
      plugin: "nav2_navfn_planner::NavfnPlanner"
      tolerance: 0.5
      use_astar: false
      allow_unknown: true

controller_server:
  ros__parameters:
    controller_frequency: 10.0
    enable_stamped_cmd_vel: true
    controller_plugins: ["FollowPath"]
    FollowPath:
      plugin: "nav2_regulated_pure_pursuit_controller::RegulatedPurePursuitController"
      desired_linear_vel: 0.30
      lookahead_dist: 0.60
      use_collision_detection: true
```

Nav2 Jazzy stack이 만드는 stamped velocity는 collision monitor를 거쳐 `/diff_drive_controller/cmd_vel`로 들어간다.

```yaml
collision_monitor:
  ros__parameters:
    cmd_vel_in_topic: "cmd_vel_smoothed"
    cmd_vel_out_topic: "/diff_drive_controller/cmd_vel"
    enable_stamped_cmd_vel: true
    observation_sources: ["scan"]
```

controller input type과 Nav2 출력 type이 모두 stamped인지 확인해야 한다.

## 실행

GUI와 RViz를 포함한 전체 stack을 시작한다.

```bash
source /opt/ros/jazzy/setup.bash
source examples/ros2_ws/install/setup.bash
ros2 launch tutorial_bot_bringup simulation.launch.py \
  world:=training gui:=true rviz:=true nav2:=true
```

launch는 `/scan`, `/odom`, `odom → base_link`가 준비된 뒤 localization과 navigation을 시작한다. 고정 sleep 뒤 Nav2를 시작하지 않는다.

## 준비 상태 확인

다른 terminal에서 다음 순서로 확인한다.

```bash
ros2 topic echo /map --once --field info.resolution
ros2 topic echo /scan --once --field header.frame_id
ros2 topic echo /odom --once --field child_frame_id
ros2 run tf2_ros tf2_echo map base_link
ros2 lifecycle nodes
ros2 action list | grep navigate_to_pose
```

`map → base_link` transform이 계속 출력되고 Nav2 lifecycle node가 active이며 `/navigate_to_pose` action이 보이면 goal을 보낼 준비가 된 것이다.

## CLI로 pose goal 보내기

실제 목표 파일 `examples/ros2_ws/src/tutorial_bot_bringup/config/project_goal.yaml`은 map 기준 `(2.0, 0.0, 0.0)`을 사용한다. 같은 goal을 CLI로 보낸다.

```bash
ros2 action send_goal --feedback \
  /navigate_to_pose nav2_msgs/action/NavigateToPose \
  '{pose: {header: {frame_id: map}, pose: {position: {x: 2.0, y: 0.0, z: 0.0}, orientation: {x: 0.0, y: 0.0, z: 0.0, w: 1.0}}}}'
```

RViz에서는 **2D Pose Estimate**로 초기 pose를 확인한 뒤 **Nav2 Goal**로 같은 위치를 클릭할 수 있다. `/plan` Path는 예정 경로, `/wheel_odom_path`는 wheel odometry의 실제 누적 경로이므로 두 display의 색을 다르게 설정하면 tracking 오차를 관찰하기 쉽다.

## 반복 자동 검증

```bash
./scripts/check_intermediate_nav2.sh --fresh-build --launch \
  --goal-name project_goal.yaml --repeat 3 \
  --position-tolerance 0.25 --yaw-tolerance 0.20
```

세 번 모두 action status 4여야 하고 최종 위치 오차는 0.25 m 이하, yaw 오차는 0.20 rad 이하여야 한다. 반복 실행은 우연한 한 번의 성공과 재현 가능한 성공을 구분한다.

도달 불가능한 goal은 `unreachable_goal.yaml`로 검사한다. 정상적인 abort 뒤에도 `/scan`, `/clock`, Nav2 node가 살아 있어야 한다. 실패 처리가 stack crash로 이어지면 안 된다.

## 문제 해결

- goal이 즉시 reject되면 action server와 goal `frame_id`를 확인한다.
- goal이 abort되면 lifecycle state, `map → odom → base_link`, `/scan`, costmap 순서로 확인한다.
- map과 scan이 어긋나면 map origin·resolution, spawn pose, initial pose를 확인한다.
- robot이 제자리에서 떨리면 footprint, inflation radius, minimum velocity, controller frequency를 확인한다.
- command는 나오지만 바퀴가 움직이지 않으면 stamped type과 `/diff_drive_controller/cmd_vel` 연결을 확인한다.
- RViz에서 map은 보이지만 RobotModel이 사라지면 Fixed Frame과 TF timestamp를 확인한다.

## 정리

Nav2 연동은 package를 launch하는 것으로 끝나지 않는다. map, `/scan`, `/odom`, TF, footprint, planner, local controller, stamped velocity가 하나의 계약으로 이어져야 한다. action status와 실제 최종 pose 오차를 함께 측정해야 navigation 성공을 판단할 수 있다.
