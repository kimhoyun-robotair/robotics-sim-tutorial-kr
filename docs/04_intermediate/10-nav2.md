# Gazebo와 Nav2 연동

> **난이도:** 중급  
> **Gazebo:** Harmonic  
> **ROS 2:** Jazzy  
> **선행 학습:** 다중 로봇

## 학습 목표

- Nav2가 요구하는 지도, 오도메트리, TF, LaserScan, 속도 명령 흐름을 연결한다.
- 지도 YAML, AMCL, 비용 지도, 경로 계획기, 컨트롤러 파라미터를 실제 코드에서 읽는다.
- RViz에 지도를 표시하고 Nav2 Goal 도구로 목표 위치와 방향을 지정한다.
- AMCL을 켠 주행과 오도메트리만 사용하는 주행을 비교한다.
- `NavigateToPose` 액션의 성공과 실패 종료를 구분한다.
- 액션 결과와 최종 위치와 자세 오차를 함께 검사한다.

## 실습 전 준비

[중급 실행 준비](index.md#intermediate-setup)를 마쳐야 한다. 새 터미널마다 저장소 루트에서 다음 명령을 실행한다.

```bash
source /opt/ros/jazzy/setup.bash
source examples/ros2_ws/install/setup.bash
```

아래 XML·Python·YAML은 설명에 필요한 부분을 발췌한 코드이다. 실행에는 본문에 표시한 저장소 파일을 사용한다. 이전 실습의 Gazebo와 launch는 `Ctrl+C`로 종료한 뒤 새 실습을 시작한다. `ros2 topic hz`와 `tf2_echo`는 계속 실행되므로, 값을 확인한 뒤 `Ctrl+C`로 멈추고 다음 명령을 입력한다.

## Gazebo와 Nav2의 책임

Gazebo는 물리 환경과 센서 데이터를 만들고, 이 예제의 ROS 컨트롤러가 바퀴 오도메트리를 계산한다. Nav2는 이 데이터를 받아 현재 위치를 추정하고 목표까지 갈 경로와 속도 명령을 만든다.

| 구성 요소 | 입력 | 출력 |
|---|---|---|
| Gazebo·브리지 | 월드와 로봇 모델 | `/scan`, `/clock` |
| DiffDrive 컨트롤러 | 바퀴 상태, 속도 명령 | `/odom`, `odom → base_link` |
| map_server | 지도 YAML과 PGM | `/map` |
| AMCL | `/map`, `/scan`, 오도메트리 TF | `/amcl_pose`, `map → odom` |
| Nav2 계획·제어 노드 | 목표, 비용 지도, 현재 위치 | `/plan`, `TwistStamped` 속도 명령 |

필요한 TF 연결은 `map → odom → base_link → lidar_link`이다. 기본 설정에서는 AMCL이 `map → odom`, DiffDrive 컨트롤러가 `odom → base_link`, `robot_state_publisher`가 `base_link → lidar_link`를 발행한다. AMCL을 끄는 비교 실습에서는 고정 TF가 `map → odom`을 대신하며, 두 발행 노드를 동시에 실행하지 않는다.

## 1. 지도 YAML 읽기

실제 지도 설정은 `examples/ros2_ws/src/tutorial_bot_gazebo/maps/training.yaml`이다.

```yaml
image: training.pgm
mode: trinary
resolution: 0.05
origin: [-5.0, -5.0, 0.0]
negate: 0
occupied_thresh: 0.65
free_thresh: 0.196
```

`resolution=0.05`는 한 픽셀이 5 cm라는 뜻이다. `origin`은 영상의 기준점을 지도 좌표계에 배치한다. PGM 지도와 `training.sdf`의 벽·장애물 위치가 맞아야 한다. 둘이 다르면 LiDAR 측정점과 지도 벽이 겹치지 않아 AMCL의 위치 추정이 흔들린다.

## 2. AMCL 좌표계와 센서 토픽

실제 설정은 `examples/ros2_ws/src/tutorial_bot_bringup/config/nav2_params.yaml`에 있다.

```yaml
amcl:
  ros__parameters:
    use_sim_time: true
    global_frame_id: map
    odom_frame_id: odom
    base_frame_id: base_link
    scan_topic: /scan
    robot_model_type: "nav2_amcl::DifferentialMotionModel"
    min_particles: 500
    max_particles: 2000
    set_initial_pose: true
    initial_pose:
      x: 0.0
      y: 0.0
      z: 0.0
      yaw: 0.0
```

`DifferentialMotionModel`은 2륜 `tutorial_bot`의 운동학에 맞는다. 4륜 Ackermann 로버를 Nav2에 연결할 때는 컨트롤러와 운동 모델, 바닥 투영 외곽선, 최소 회전반경을 함께 다시 검토해야 한다.

## 3. 지역·전역 비용 지도

비용 지도(costmap)는 장애물 주변이나 통과하기 어려운 곳에 높은 비용을 부여한 격자 지도이다. 지역 비용 지도는 `odom` 기준에서 로봇 주변의 작은 구역을 따라 이동한다. 전역 비용 지도는 `map` 기준으로 전체 지도와 장애물을 관리한다.

```yaml
local_costmap:
  local_costmap:
    ros__parameters:
      global_frame: odom
      robot_base_frame: base_link
      rolling_window: true
      width: 3
      height: 3
      resolution: 0.05
      footprint: "[[0.24, 0.22], [0.24, -0.22], [-0.24, -0.22], [-0.24, 0.22]]"
      plugins: ["voxel_layer", "inflation_layer"]
      voxel_layer:
        plugin: "nav2_costmap_2d::VoxelLayer"
        observation_sources: scan
        scan:
          topic: /scan
          data_type: "LaserScan"
          marking: true
          clearing: true
```

```yaml
global_costmap:
  global_costmap:
    ros__parameters:
      global_frame: map
      robot_base_frame: base_link
      plugins: ["static_layer", "obstacle_layer", "inflation_layer"]
      static_layer:
        plugin: "nav2_costmap_2d::StaticLayer"
        map_subscribe_transient_local: true
      obstacle_layer:
        plugin: "nav2_costmap_2d::ObstacleLayer"
        observation_sources: scan
        scan:
          topic: /scan
          data_type: "LaserScan"
          marking: true
          clearing: true
```

바닥 투영 외곽선은 시각 형상 크기가 아니라 충돌 형상의 바닥 투영과 안전 여유를 기준으로 정한다. 실제 몸체가 바닥 투영 외곽선보다 크면 경로 계획기가 통과 가능하다고 판단한 좁은 공간에서 충돌할 수 있다.

## 4. 경로 계획기와 경로 추종기

전역 경로 계획기와 지역 컨트롤러 플러그인을 이름으로 선택한다.

```yaml
planner_server:
  ros__parameters:
    planner_plugins: ["GridBased"]
    GridBased:
      plugin: "nav2_navfn_planner::NavfnPlanner"
      tolerance: 0.5
      use_astar: false
      allow_unknown: true

controller_server:
  ros__parameters:
    controller_frequency: 10.0
    enable_stamped_cmd_vel: true
    controller_plugins: ["FollowPath"]
    FollowPath:
      plugin: "nav2_regulated_pure_pursuit_controller::RegulatedPurePursuitController"
      desired_linear_vel: 0.30
      lookahead_dist: 0.60
      use_collision_detection: true
```

Jazzy의 Nav2는 기본값으로 `Twist`를 사용한다. 이 예제는 `controller_server`, `behavior_server`, `velocity_smoother`, `collision_monitor`에 `enable_stamped_cmd_vel: true`를 지정해 모두 `TwistStamped`를 사용한다. 속도 명령은 충돌 감시 노드(collision monitor)를 거쳐 `/diff_drive_controller/cmd_vel`로 들어간다. [Nav2 Jazzy의 TwistStamped 지원](https://docs.nav2.org/migration/Iron.html)을 참고한다.

```yaml
collision_monitor:
  ros__parameters:
    cmd_vel_in_topic: "cmd_vel_smoothed"
    cmd_vel_out_topic: "/diff_drive_controller/cmd_vel"
    enable_stamped_cmd_vel: true
    observation_sources: ["scan"]
```

한 노드만 타입을 바꾸면 중간에서 메시지가 끊긴다. `ros2 topic info /diff_drive_controller/cmd_vel -v`로 타입이 `geometry_msgs/msg/TwistStamped`인지 확인한다.

## 실행

Gazebo와 RViz를 함께 실행하고 AMCL로 현재 위치를 추정한다. 코드를 갱신한 뒤에는 [중급 프로젝트의 빌드 절차](11_project-autonomous-bot.md)를 먼저 실행한다.

```bash
source /opt/ros/jazzy/setup.bash
source examples/ros2_ws/install/setup.bash
ros2 launch tutorial_bot_bringup simulation.launch.py \
  world:=training gui:=true rviz:=true nav2:=true amcl:=true
```

`simulation.launch.py`는 `/scan`, `/odom`, `odom → base_link`를 확인한 뒤 `nav2.launch.py`를 실행한다. `nav2.launch.py`는 map_server와 AMCL을 활성화하고, `/map`과 `map → base_link`가 준비되면 경로 계획과 주행 제어를 시작한다. 각 노드의 활성화는 Nav2의 lifecycle manager가 담당하므로 RViz 패널에서도 현재 상태를 확인할 수 있다.

RViz는 `examples/ros2_ws/src/tutorial_bot_bringup/rviz/nav2.rviz`를 읽는다. Fixed Frame이 `map`으로 설정되어 있고, 지도와 로봇, LiDAR, 계획 경로, 주행 궤적이 표시된다. 상단의 **2D Pose Estimate**, **Nav2 Goal** 도구와 왼쪽의 **Navigation 2** 패널도 함께 열린다.

## AMCL 켜고 끄기

`amcl` 옵션은 실행할 때 정한다. 모드를 바꾸려면 기존 launch를 `Ctrl+C`로 종료한 뒤 다시 실행한다.

| 실행 옵션 | 위치를 계산하는 방법 | RViz 기준 좌표계 |
|---|---|---|
| `nav2:=true amcl:=true` | AMCL이 지도와 LiDAR로 바퀴 오도메트리의 오차를 보정한다 | `map` |
| `nav2:=true amcl:=false` | 시작할 때의 `map`과 `odom`을 일치시키고 바퀴 오도메트리만 사용한다 | `map` |
| `nav2:=false` | map_server와 AMCL, Nav2를 실행하지 않는다. 수동 주행을 확인할 때 사용한다 | `odom` |

AMCL 없이 같은 목표를 주행하려면 다음처럼 실행한다.

```bash
ros2 launch tutorial_bot_bringup simulation.launch.py \
  world:=training gui:=true rviz:=true nav2:=true amcl:=false
```

이 모드에서도 map_server가 `/map`을 발행하므로 RViz에 지도가 뜨고 Nav2 Goal을 사용할 수 있다. `/amcl` 노드와 `/amcl_pose`는 생기지 않는다. 로봇이 지도 원점에서 +x 방향을 향해 출발하는 현재 예제에 맞춰 `map → odom`을 고정한다. 바퀴가 미끄러져도 지도에 맞춰 위치를 바로잡지 않으므로 오래 주행할수록 실제 위치와 표시 위치가 달라질 수 있다.

**2D Pose Estimate는 AMCL을 켰을 때 사용한다.** AMCL을 끈 상태에서는 이 도구로 고정 TF나 오도메트리의 원점을 바꿀 수 없다. 다른 위치 추정 노드를 연결하려면 이 예제의 고정 TF를 함께 실행하지 않도록 구성해야 한다.

## 준비 상태 확인

다른 터미널에서 다음 순서로 확인한다.

```bash
ros2 topic echo /map --once --qos-durability transient_local --field info.resolution
ros2 topic echo /scan --once --field header.frame_id
ros2 topic echo /odom --once --field child_frame_id
ros2 run tf2_ros tf2_echo map base_link
ros2 lifecycle get /map_server
ros2 lifecycle get /amcl
ros2 lifecycle get /planner_server
ros2 lifecycle get /controller_server
ros2 lifecycle get /bt_navigator
ros2 action list | grep navigate_to_pose
```

첫 세 조회는 각각 `0.05`, `lidar_link`, `base_link`를 보여야 한다. `tf2_echo`에서 변환을 확인한 뒤 `Ctrl+C`로 종료한다. 각 `lifecycle get`이 `active [3]`을 반환하고 `/navigate_to_pose` 액션이 보이면 목표를 보낼 준비가 된 것이다. 노드 이름이 목록에 존재하는 것만으로 활성화를 판단하지 않는다.

`amcl:=false`로 실행했다면 `/amcl` 상태 조회는 건너뛴다. Navigation 2 패널의 Localization 표시는 위치 추정용 lifecycle manager가 관리하는 노드의 상태이다. AMCL을 끈 경우에는 map_server만 관리하므로 이 표시가 `active`여도 AMCL이 실행 중이라는 뜻은 아니다.

## RViz에서 목표를 지정해 주행하기

1. 왼쪽 **Displays → Global Options**에서 Fixed Frame이 `map`인지 확인한다. **Map** 항목은 `/map`, Durability는 `Transient Local`이어야 한다. 저장된 설정을 그대로 불러왔다면 따로 바꿀 필요가 없다.
2. 지도 위에 파란 로봇과 LiDAR 점이 나타나는지 확인한다. **Navigation 2** 패널의 Navigation과 Localization이 모두 `active`가 될 때까지 기다린다.
3. AMCL을 켰는데 로봇의 위치나 방향이 지도와 어긋나면 **2D Pose Estimate**를 누른다. 지도에서 현재 로봇 위치를 누른 채 앞쪽 방향으로 끌었다가 놓는다. 이 동작은 목표를 보내는 것이 아니라 AMCL에 초기 위치와 방향을 알려 주는 과정이다. 예제는 원점에서 +x 방향으로 출발하므로 처음부터 위치가 맞으면 이 단계는 건너뛴다.
4. 상단의 **Nav2 Goal**을 누른다. 로봇 앞쪽의 빈 공간을 누른 채 도착 후 바라볼 방향으로 끌었다가 놓는다. 첫 목표는 `(2.0, 0.0)` 부근으로 정한다. 현재 화면에서는 로봇 오른쪽으로 2 m 떨어진 지점이며, 화살표도 오른쪽을 향하게 한다.
5. 하늘색 **Nav2 Plan**이 나타나고 로봇이 경로를 따라 움직이는지 확인한다. 주황색 **Wheel Odom Trajectory**는 바퀴 오도메트리로 기록한 주행 궤적이다. 두 선을 비교하면 계획한 경로를 얼마나 잘 따라갔는지 볼 수 있다.
6. 도착 후 Navigation 2 패널의 Feedback이 `reached`로 바뀌는지 확인한다. 액션의 성공 상태 `SUCCEEDED`를 패널에서 이렇게 표시한다. 주행 도중 목표를 취소하려면 패널의 **Cancel**을 누른다.

벽이나 검은 장애물 안을 목표로 지정하면 경로를 찾지 못할 수 있다. 처음에는 장애물에서 충분히 떨어진 빈 공간을 선택한다. **2D Pose Estimate**와 **Nav2 Goal**은 모두 화살표를 그리지만, 전자는 현재 위치를 알려 주고 후자는 도착할 위치를 정한다.

AMCL이 추정하는 위치 후보를 보고 싶으면 Displays의 **AMCL Particles**를 켠다. 장애물 주변의 주행 비용을 살펴볼 때는 **Global Costmap**이나 **Local Costmap**을 켠다. 기본 화면에서는 지도와 경로가 잘 보이도록 이 항목들을 꺼 두었다.

도구가 보이지 않으면 예전 RViz 설정을 연 상태인지 확인한다. **File → Open Config**에서 설치된 `tutorial_bot_bringup/rviz/nav2.rviz`를 다시 열거나, 현재 launch를 종료한 뒤 위 실행 명령으로 다시 시작한다. Nav2 Goal 도구와 Navigation 2 패널이 함께 있어야 마우스로 지정한 목표가 Nav2 액션으로 전달된다.

## CLI로 위치와 자세 목표 보내기

실제 목표 파일 `examples/ros2_ws/src/tutorial_bot_bringup/config/project_goal.yaml`은 지도 기준 `(2.0, 0.0, 0.0)`을 사용한다. 같은 목표를 CLI로 보낸다.

```bash
ros2 action send_goal --feedback \
  /navigate_to_pose nav2_msgs/action/NavigateToPose \
  '{pose: {header: {frame_id: map}, pose: {position: {x: 2.0, y: 0.0, z: 0.0}, orientation: {x: 0.0, y: 0.0, z: 0.0, w: 1.0}}}}'
```

이 명령은 RViz에서 목표를 지정했을 때와 같은 `NavigateToPose` 액션을 사용한다. 좌표를 정확히 반복해서 보내려면 CLI가 편리하고, 지도에서 빈 공간을 골라 주행하려면 Nav2 Goal이 편리하다. 한 목표의 결과를 확인하거나 취소한 뒤 다음 목표를 보낸다.

```bash
./scripts/check_intermediate_nav2.sh --fresh-build --launch \
  --evidence /tmp/tutorial-intermediate-nav2 \
  --goal-name project_goal.yaml --repeat 3 \
  --position-tolerance 0.25 --yaw-tolerance 0.20
```

스크립트는 실행마다 시뮬레이션을 새로 시작한다. 세 번 모두 액션 상태 `4`(SUCCEEDED)여야 하고 최종 위치 오차는 0.25 m 이하, 요 각도 오차는 0.20 rad 이하여야 한다. 반복 실행은 우연한 한 번의 성공과 재현 가능한 성공을 구분한다.

도달 불가능한 목표는 `unreachable_goal.yaml`로 검사한다. 정상적인 실패 종료 뒤에도 `/scan`, `/clock`, Nav2 노드가 살아 있어야 한다. 실패 처리가 시스템 비정상 종료로 이어지면 안 된다.

## 문제 해결

- 목표가 즉시 거절되면 액션 서버와 목표 `frame_id`를 확인한다.
- 목표가 실패 종료되면 수명주기 상태, `map → odom → base_link`, `/scan`, 비용 지도 순서로 확인한다.
- 지도와 scan이 어긋나면 지도 `origin`·`resolution`, 로봇 생성 위치, AMCL 초기 위치를 확인한다.
- 로봇이 제자리에서 떨리면 바닥 투영 외곽선, 장애물 주변 여유 거리, 최소 속도, 컨트롤러 실행 주기를 확인한다.
- 명령은 나오지만 바퀴가 움직이지 않으면 시간 정보가 포함된 타입과 `/diff_drive_controller/cmd_vel` 연결을 확인한다.
- RViz에서 지도는 보이지만 RobotModel이 사라지면 Fixed Frame과 TF 타임스탬프를 확인한다.
- 지도가 뜨지 않으면 `/map_server`가 `active`인지, Map 항목의 토픽이 `/map`이고 Durability가 `Transient Local`인지 확인한다.
- Nav2 Goal을 눌러도 반응이 없으면 Navigation 2 패널이 열려 있는지와 `/navigate_to_pose` 액션 서버의 상태를 확인한다.
- `amcl:=false`에서는 `/amcl_pose`를 기다리지 않는다. 위치는 `map → base_link` TF와 `/odom`으로 확인한다.

## 정리

Nav2 연동은 패키지를 launch하는 것으로 끝나지 않는다. 지도, `/scan`, `/odom`, TF, 바닥 투영 외곽선, 경로 계획기, 지역 컨트롤러, 시간 정보가 포함된 속도 명령이 하나의 흐름으로 연결되어야 한다. 액션 상태와 실제 최종 위치와 자세 오차를 함께 측정해야 자율주행 성공을 판단할 수 있다.
