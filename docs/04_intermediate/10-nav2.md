# Gazebo와 Nav2 연동

> **난이도:** 중급  
> **Gazebo:** Harmonic  
> **ROS 2:** Jazzy  
> **선행 학습:** 다중 로봇

## 학습 목표

- Nav2가 요구하는 map, odometry, TF, LaserScan, 속도 명령 흐름을 연결합니다.
- `NavigateToPose` action의 성공과 실패를 구분합니다.
- 실제 최종 pose 오차를 검사합니다.

## 배경 지식

Gazebo가 Nav2를 대신하지 않습니다. Harmonic은 sensor와 물리를 제공하고, AMCL이 `map → odom`, controller가 `odom → base_link`, LiDAR가 `/scan`을 제공합니다. Nav2의 출력은 stamped velocity 명령으로 diff drive controller에 전달됩니다.

## 예제 파일

- `examples/ros2_ws/src/tutorial_bot_bringup/config/nav2_params.yaml`
- `examples/ros2_ws/src/tutorial_bot_bringup/config/project_goal.yaml`
- `examples/ros2_ws/src/tutorial_bot_gazebo/maps/training.yaml`
- `examples/ros2_ws/src/tutorial_bot_gazebo/worlds/training.sdf`

## 실행

```bash
./scripts/check_intermediate_nav2.sh --fresh-build --launch \
  --goal-name project_goal.yaml --repeat 3 \
  --position-tolerance 0.25 --yaw-tolerance 0.20
```

## 결과 확인

세 번 모두 action status 4여야 하며, 최종 위치 오차는 0.25 m 이하, yaw 오차는 0.20 rad 이하여야 합니다. 검증된 실행에서는 위치 오차가 약 0.05–0.11 m 범위였습니다.

## 동작 원리

map server와 AMCL이 전역 기준을 만들고 planner가 경로를 계산합니다. controller는 local costmap과 odometry를 사용해 `/cmd_vel`을 생성하며, `gz_ros2_control` diff drive가 바퀴를 움직입니다.

## 계산 예제: pose 허용오차

<div class="course-worked" data-worked-example="nav2-tolerance" markdown="1">
goal \((2.0,1.0)\), 최종 pose \((1.92,1.06)\)이면 위치 오차는 \(e_p=\sqrt{(-0.08)^2+0.06^2}=0.10\,\mathrm{m}\)로 0.25 m 기준 안입니다. yaw 오차는 \(e_\psi=\operatorname{atan2}(\sin(\psi-\psi^*),\cos(\psi-\psi^*))\)로 감싸며 0.20 rad 이하여야 합니다. costmap obstacle 때문에 도달할 수 없는 fixture는 status 6 abort가 올바른 관측입니다.
</div>

## 문제 해결

goal이 abort되면 lifecycle node 활성 상태, `map → odom → base_link`, `/scan`, costmap을 순서대로 확인합니다. 도달 불가능 goal은 status 6으로 끝나는 것이 올바른 실패 처리입니다.

## 정리

Nav2 성공은 action 결과만이 아니라 TF, sensor, controller, 최종 pose 오차가 함께 맞아야 합니다.
