# 101. 블록 탑을 보면서 다음 행동을 선택하기

## 이번에 배우는 것

**Franka가 네 블록을 정해진 순서로 쌓는 과정을 관찰하고, 현재 탑과 그리퍼 상태가 집기·놓기 판단으로 이어지는 구조를 읽습니다.**

탑 쌓기를 “파란 블록 집기, 옮기기, 놓기…”라는 고정 순서로만 작성하면 도중에 블록이 옮겨졌을 때 대응하기 어렵습니다. 이번 behavior는 매번 현재 배치를 읽어 아직 할 일을 판단합니다. 잡기와 놓기의 짧은 구간에는 행동이 중간에 바뀌지 않도록 잠금도 사용합니다.

| 구성 | 실습 값 또는 파일 | 역할 |
|---|---|---|
| 실행기 | `run.py` | Franka, 네 블록, 지면 생성 |
| 행동 | `block_stacking_behavior.py` | 관찰·집기·놓기·복구 판단 |
| 블록 한 변 | `0.0515` m | 층 높이와 탑 판정의 기준 |
| 탑 바닥 위치 | `(0.25, 0.3, 0)` m | 다음 블록을 놓을 기준점 |
| 아래부터 쌓을 순서 | Blue → Yellow → Green → Red | 탑 완성 여부의 조건 |

## 1. 네 블록 쌓기 실행하기

Isaac Sim 5.1, 지원 NVIDIA RTX GPU와 Franka 자산 접근이 필요합니다. 저장소 루트에서 실행하세요.

```bash
~/isaacsim/python.sh src/101_digital_twin_cortex_4_franka_block_stacking/run.py --interactive
```

1. `/World/Franka`와 `/World/Obs/`의 네 블록이 로드되면 Play를 누릅니다.
2. 초기 블록은 X=0.3~0.7 m, Y=-0.4 m에 나란히 있습니다. 첫 블록을 집어 목표 탑 위치로 옮기는 과정을 봅니다.
3. 네 층을 관찰할 수 있도록 창을 열어 둡니다. 끝내려면 창을 닫으세요.

`--interactive`를 빼면 자동 Play합니다. `--steps 1800`은 해당 물리 단계에서 실행을 끝내며 **네 층 완성을 기다리는 옵션이 아닙니다.** `--headless`는 기본 1800단계지만 화면에서 집기와 지지를 확인하는 이번 관찰에는 GUI를 사용합니다.

### 코드에서 볼 부분

`run.py`는 블록을 `DynamicCuboid`로 만들고 다음 등록을 수행합니다.

```python
robot.register_obstacle(cube)
```

블록은 물리적으로 떨어지고 부딪치는 강체인 동시에, 팔의 동작 생성기가 피해야 할 장애물입니다. 이 두 역할을 구분하면 뒤에서 “집을 물체의 회피를 끈다”는 설정을 이해하기 쉽습니다. 집기 위해 접근할 때는 그 블록을 계속 피하면 안 되지만 물리 접촉은 여전히 필요합니다.

### 실행 결과 확인하기

탑의 색 순서와 물리 상태를 함께 확인하세요.

- 목표 XY 부근에 아래부터 **Blue, Yellow, Green, Red**가 놓이는지 봅니다.
- 그리퍼가 열린 뒤에도 블록이 아래층에 지지되어 남아 있는지 확인합니다.
- 탑이 완성되면 home 행동을 선택하지만 앱은 계속 열려 있습니다.

콘솔의 `<placing block>`은 놓기 목표에 손끝이 충분히 가까워졌다는 뜻입니다. 아직 그리퍼를 열고 블록이 안정되는 과정이 남아 있으므로, 이 로그 하나를 적재 성공으로 읽지 마세요. `in tower`를 포함한 상세 진단 문자열은 context에 저장되며 이 실행기에는 자동 표시 UI가 없습니다.

## 2. 탑 상태에서 다음 행동까지 따라가기

핵심 출발점은 `BlockPickAndPlaceDispatch.decide()`입니다.

```python
if ct.block_tower.is_complete:
    return DfDecision("go_home")
if ct.is_gripper_clear:
    return DfDecision("pick")
else:
    return DfDecision("place")
```

탑이 완성되었는지 먼저 판단하고, 남은 작업이 있으면 손에 블록이 있는지로 집기와 놓기를 나눕니다. 어떤 블록을 고를지, 어떤 자세로 접근할지는 그 아래 계층에서 결정합니다.

### 코드에서 볼 부분

`monitor_block_tower()`는 목표 XY에서 블록 반 높이인 `0.02575` m 이내의 블록을 모으고 Z가 낮은 순서로 정렬합니다. 현재 그리퍼에 있다고 판단한 블록은 탑에서 제외합니다. 따라서 이 탑 목록은 과거에 “놓았다”는 명령 횟수가 아니라 **현재 위치를 다시 읽어 만든 목록**입니다.

다음 층의 중심 높이는 다음 코드로 구합니다.

```python
h = self.height
fractional_margin = 0.025
dz = (h + 0.5 + fractional_margin) * self.block_height
```

`h`가 현재 층수입니다. `0.5`는 새 블록 중심까지의 반 높이, `0.025`는 블록 높이에 대한 작은 여유 비율입니다. 여유는 2.5 cm가 아니라 `0.025 × 0.0515 = 0.0012875` m, 약 1.29 mm입니다. 놓기 목표와 최종 지지된 중심 높이가 조금 달라도 자연스럽습니다.

집기 단계의 RLDS는 현재 조건에서 실행 가능한 행동을 우선순위로 선택하는 구조입니다. `make_pick_rlds()`의 등록 순서는 reach → pick → open이지만 검사 우선순위는 뒤쪽부터입니다. 손가락이 닫힌 채 물체에 가까워지면 먼저 열고, 잡을 자세에 도달하면 pick을 수행하며, 나머지 상황에서는 접근합니다.

잡기 시퀀스의 순서는 다음과 같습니다.

```text
행동 경로 잠금 → 그리퍼 닫기 → 블록 들어 올리기
              → 손에 든 블록을 논리 상태에 기록 → 잠금 해제
```

잠금은 이 짧은 동작 도중 상위 판단이 다른 가지로 전환하는 것을 막습니다. 이후 `monitor_gripper_has_block()`은 블록과 손끝이 0.1 m보다 멀어졌다면 잡고 있다는 상태를 해제합니다. 명령으로 쓴 상태를 후속 관찰로 보완하는 구조입니다.

### 실행 결과 확인하기

아직 집지 않은 블록을 도달 가능한 빈 위치로 조금 옮겨 보세요. 팔이 새 위치에 접근하는지 확인합니다. 완성한 탑의 맨 위 블록을 탑 옆으로 옮기면 탑 목록이 줄어들고, 빠진 블록을 다시 쌓으려 하는지 관찰할 수 있습니다.

순서가 잘못된 탑은 위 블록을 치운 뒤 올바른 순서로 다시 구성하는 경로가 있습니다. 다만 위치 기반 판정만으로 지지 접촉까지 증명하지는 않으므로 실제 화면도 함께 봅니다.

## 3. 관찰과 행동의 연결 정리

```text
블록 위치·그리퍼 상태 관찰
    → 현재 탑의 층수와 순서 판단
    → 집기 / 놓기 / home 선택
    → 접근·그리퍼·lift 수행
    → 바뀐 배치를 다시 관찰
```

탑 쌓기의 반응성은 이 순환에서 나옵니다. 잠금은 관찰을 없애는 기능이 아니라 잡기·놓기의 중요한 구간에 행동 전환을 제한하는 기능입니다.

## 4. 간단한 확인 실험

behavior 맨 아래 `make_decider_network()`의 탑 위치에서 **X만 `0.25`에서 `0.30`으로** 바꾸고 새로 실행하세요.

색 순서와 블록 크기는 그대로인데 탑이 5 cm 옆에 만들어지는지 봅니다. 층 높이를 계산하는 공식은 그대로이므로 높이를 바꾸는 실험이 아닙니다. 완료 후 X를 원래 값으로 되돌리세요.

## 실행할 때 막히면

- **`block too close to robot base` 또는 `block too far away`**: 블록 중심의 원점 거리가 각각 0.25 m 미만 또는 0.81 m 초과인지 확인하세요. 원래 배치 근처로 돌려놓습니다.
- **블록을 옮겼는데 home에서 기다림**: 탑이 두 층 이상일 때 대상 블록이 탑 기준점의 0.15 m 안쪽이면 별도 접근 제한에 걸릴 수 있습니다. 빈 위치로 조금 더 옮겨 보세요.
- **팔이 블록을 관통하거나 탑이 무너짐**: 순간 이동으로 손가락 안에 블록을 겹치게 만들지 않았는지 확인하세요. 회피 억제와 물리 Collider 설정은 다릅니다.
- **단계 종료 메시지만 나옴**: 제한 시간 안에 관찰한 작업 범위만 기록하세요. 자동 종료가 탑 완성을 검사하지 않습니다.
